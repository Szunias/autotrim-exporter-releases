# AutoTrim Exporter 3.4.4

A correctness release on top of 3.4.3, plus the accessibility work the interface
owed. Six checks were reporting things that were not true, two REAPER render
settings that AutoTrim does not own were being allowed to shape the delivered
file, and the interface had no tooltips, no help and no way back to defaults.
Rendering engine 2.11.5.

The layout is the same as 3.4.3 — see the
[3.4.3 interface tour](3.4.3.md) for the visual walkthrough — but the interface
itself has changed in the ways listed under *Interface* below.

## Fixed: settings AutoTrim does not own were shaping the delivery

**A project low-pass render fade no longer becomes the delivery fade.**

REAPER 7.48 added Low Pass Fades, where a render fade is a filter sweep rather
than an amplitude ramp. AutoTrim sizes its fades from the boundaries it detects
and pins their shape to linear, but it never cleared this setting — so with the
option on, your delivery got a filtered tail you did not ask for. Worse, the
delivery QC edge check then blamed *you* for a fade-out that "did not reach
silence", when the render had never ramped the amplitude down in the first
place. It is now cleared for the whole export, so the analysis pass measures the
same unfiltered signal the delivery renders, and restored with the other render
settings afterwards. Builds older than 7.48 have no such setting and are
unaffected.

**A combined render keeps the project's FX-initialisation delay.**

REAPER can delay the start of a render so instruments finish loading their
samples. It changes nothing about *what* is rendered, only whether the chain is
ready when rendering starts — but AutoTrim's fixed render source overwrote the
whole setting and dropped it. A sampler still streaming its patch rendered
missing or quiet attacks, and neither the length check nor the peak check can
see that the notes are gone. Per-item renders read media items directly and have
no instrument to wait for, so they do not pay the delay.

## Fixed: names that were not the names you would get

**A delivery profile no longer hijacks the imported name queue.**

Applying a profile restores its captured delivery name, but left the queue index
pointing at the entry it replaced. The window then displayed `Names 3/10` for a
name that came from nowhere in that list, and with auto-advance on, your first
export overwrote the profile's own name with the next entry.

**The classic window's file-name preview matches what a per-item export writes.**

With UCS naming on, the preview built the name with the combined-render rule, so
a batch of items was previewed under one shared FXName. A per-item delivery
derives FXName from each item — the preview was promising a filename the render
would never produce, in the one mode where names differ per file.

## Interface

- **The dependency indicator can report something other than fine.** It read
  `Engine ready` unconditionally, including with SWS missing while the loudness
  column three panes away read `no SWS`. It now reports Ready, Limited mode or
  Needs attention, names the missing piece, and surfaces an export folder that
  failed its write test.
- **Preflight severity is no longer carried by colour alone.** A blocker and a
  warning shared one bullet and differed only in hue — the distinction a
  red/green-blind reader cannot make, and the one that decides whether the
  export runs at all.
- **Helper text meets WCAG AA.** The small muted text measured 4.02:1 against
  input backgrounds, which is exactly where the field hints live.
- **Tooltips and help.** There were none, anywhere. The controls that decide the
  delivery now explain themselves, the destination field shows the full path it
  is too narrow to display, and F1 opens the keyboard shortcuts plus what your
  installation can and cannot measure. F1 works while a field has focus, which
  is when you are actually stuck.
- **No click target is under 32 px.** The links and the three per-row history
  actions were around 18 px — the size that hurts on a trackpad or a touch
  display, repeated on every row of a long list.
- **A blocking threshold combination is reported where it is caused.** A tail
  threshold above the start threshold blocks the export; you used to discover
  that from a status line after pressing Export.
- **Restore default settings**, from the help popup, behind a confirmation that
  names both halves: delivery settings go back to their first-run values, while
  your export history, the Undo journal for recent deliveries and your saved
  delivery profiles are kept.

## Also fixed in 3.4.4

**An offline effect on the master no longer blocks the export.**

Preflight is not optional and a blocker stops the render, so 3.4.3 refused to
deliver from any project that had an offline plugin on the master — a
deliberately offlined analyser, or a plugin you do not own on the machine you
are working on. The reason it gave was also wrong: REAPER unloads an offline
effect, so it processes nothing during playback either, and the delivered file
matches what you are hearing. That is the same reasoning the chain scan already
used to ignore a *bypassed* effect.

It is now a warning that states what is actually true: nothing is applied
either way, and if the effect went offline because the plugin failed to load,
the master chain is not doing work it was built to do.

**The non-reproducible-chain note no longer fires on deterministic sessions.**

It compared the peak of the analysis pass against the peak of the delivery
pass — but those two passes never cover the same window. The analysis pass
renders the untrimmed selection plus up to 30 seconds of tail scan; the
delivery pass renders the trimmed region with a fade. Their peaks differ for
entirely ordinary reasons: other material inside the longer window, a master
limiter whose gain reduction depends on what preceded the point being measured,
a fade across the loudest sample.

The comparison now requires the two passes to have covered the same window with
no fade applied. Where that cannot be shown, no claim is made. Catching every
non-deterministic chain needs a second render over an identical window — a
render pass you agree to spend, not an inference from two passes that were
never meant to match.

**A zero-length delivery is a failure again.**

An empty render carries no peak and no loudness measurement, so the silence
check could not see it and the duration gates added in 3.4.0 supplied a
plain-sounding reason for every missing number. The most complete possible
failure of an export was leaving the batch as "PASS with gaps".

**A report cell no longer blames a file's length for a number nothing
measured.**

Without a loudness measurement API present, a short file read
`not measurable: file shorter than 0.4 s` while a long one read `not measured` —
the same missing dependency reported as two different causes, one of which
reads as normal. The file's length is now given as the reason only where a
measurement exists and the standard says it cannot be used at that duration.

## Verification

171 engine scenarios and 89 interface contract checks pass. Twelve deliberate
mutations were made to the changed code — including loosening the 400 ms
gating threshold from ITU-R BS.1770-5 and the one-minute Loudness Range floor
from EBU R128 — and all twelve turned the suite red. The first mutation run
found that the standards' own numbers were not pinned by any test at all; that
is now a scenario of its own, asserted at the exact boundary.

Every bit this release writes into REAPER's render settings was re-checked
against the published `GetSetProjectInfo` documentation rather than against the
assumptions the code was originally written on. That is how both render-setting
faults above were found.

The interface work is pinned by contract checks of its own, because these are
the properties that rot quietly: a colour is easy to darken, a severity marker
easy to unify, a tooltip easy to drop while refactoring the control it hung on.

## Upgrading

Replace the two script files from the package. Settings, delivery profiles,
export history and the Undo journal all carry over unchanged.
