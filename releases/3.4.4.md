# AutoTrim Exporter 3.4.4

A correctness patch on top of 3.4.3. Nothing here is a new feature. Four checks
introduced with the 3.4 feature set were reporting things that were not true,
and one of them refused to export projects that were entirely correct. Rendering
engine 2.11.5.

The interface is unchanged from 3.4.3 — see the
[3.4.3 interface tour](3.4.3.md) for the visual walkthrough.

## Fixed in 3.4.4

**An offline effect on the master no longer blocks the export.**

Preflight is not optional and a blocker stops the render, so 3.4.3 refused to
deliver from any project that had an offline plugin on the master — a
deliberately offlined analyser, or a plugin you do not own on the machine you
are working on. The reason it gave was also wrong: REAPER unloads an offline
effect, so it processes nothing during playback either, and the delivered file
matches what you are hearing. That is the same reasoning the chain scan already
used to ignore a *bypassed* effect.

It is now a warning that states what is actually true: nothing is applied
either way, and if the effect went offline because the plugin failed to load,
the master chain is not doing work it was built to do.

**The non-reproducible-chain note no longer fires on deterministic sessions.**

It compared the peak of the analysis pass against the peak of the delivery
pass — but those two passes never cover the same window. The analysis pass
renders the untrimmed selection plus up to 30 seconds of tail scan; the
delivery pass renders the trimmed region with a fade. Their peaks differ for
entirely ordinary reasons: other material inside the longer window, a master
limiter whose gain reduction depends on what preceded the point being measured,
a fade across the loudest sample.

The comparison now requires the two passes to have covered the same window with
no fade applied. Where that cannot be shown, no claim is made. Catching every
non-deterministic chain needs a second render over an identical window — a
render pass you agree to spend, not an inference from two passes that were
never meant to match.

**A zero-length delivery is a failure again.**

An empty render carries no peak and no loudness measurement, so the silence
check could not see it and the duration gates added in 3.4.0 supplied a
plain-sounding reason for every missing number. The most complete possible
failure of an export was leaving the batch as "PASS with gaps".

**A report cell no longer blames a file's length for a number nothing
measured.**

Without a loudness measurement API present, a short file read
`not measurable: file shorter than 0.4 s` while a long one read `not measured` —
the same missing dependency reported as two different causes, one of which
reads as normal. The file's length is now given as the reason only where a
measurement exists and the standard says it cannot be used at that duration.

## Verification

166 engine scenarios and 78 interface contract checks pass. Twelve deliberate
mutations were made to the changed code — including loosening the 400 ms
gating threshold from ITU-R BS.1770-5 and the one-minute Loudness Range floor
from EBU R128 — and all twelve turned the suite red. The first mutation run
found that the standards' own numbers were not pinned by any test at all; that
is now a scenario of its own, asserted at the exact boundary.

## Upgrading

Replace the two script files from the package. Settings, delivery profiles,
export history and the Undo journal all carry over unchanged.
