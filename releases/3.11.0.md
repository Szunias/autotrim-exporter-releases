# AutoTrim Exporter 3.11.0

The biggest release since 3.4.4 and the first public one since. It rolls up
3.4.5 through 3.10.0, none of which was published, plus the fixes from a final
review of the combined code. These notes are written for 3.4.4 users and cover
what changes when you upgrade. Rendering engine 2.14.0 (3.4.4 shipped 2.11.5).

Before your first export:

- **3.4.4 wrote every forced WAV bit depth wrongly**, built-in profiles
  included. Spot-check your library (see *Fixed*).
- **On macOS and Linux, the export folder must support hard links.**
- **With manual thresholds and 2 render passes, a combined render now stops**
  when its tail outlasts the 5-second scan, instead of delivering it cut.
- **The system folder opens after a successful export** unless you set
  **After export** to **Stay here**.

## Queue mode and batch delivery

**Mark a sound, mark the next, export once: `Name_01`, `Name_02`, `Name_03`.**

Queue is a third render mode beside Per item and Combined render. Select a
sound's layers, press `Q` (or **Add group**), repeat for the next sound, then
export once. No more retyping `Impact_1`, `Impact_2` between exports. Each group
renders exactly like Combined render, report and Undo included, and is numbered
by its place in the queue. With the name field empty, each group uses its own
take name.

- **Build it fast.** **Queue regions** marks one group per project region,
  named after the region. **Batch tools… → Add separated groups** splits a
  selection of several sounds by clip position, joining clips closer than
  **Join gap (ms)**.
- **Name each file.** A variant tag lands before the number (`Bow_dry_01`). A
  **Group file name** replaces the shared name and drops the number, so
  `ItemGrab`, `ItemDrop` and `CraftingSuccess` come out of one run; **Use take
  names** or a pasted list fills them in bulk. Duplicate names block the batch
  before anything renders.
- **Groups page (`7`)** shows each group's filename, tracks, item counts,
  position and length, with **Audition group** and **Select in REAPER**, and
  calls out muted tracks.
- **Keep it with the project.** Choose **Save queue in project**, then save the
  project; **Load queue from project** brings it back. Closing the window does
  not save queue changes.
- **Deliver only revisions.** **Include in export** and **Only this group**
  keep every number, so group 3 still writes `_03`. **Update from selection**
  swaps a revised group's layers and keeps its slot and name.

The queue remembers each item's identity. A group that loses a layer blocks the
batch until you restore, update or exclude it, and no unrelated clip is ever
substituted. **Colour groups in the arrange** is opt-in: it writes item colours
and restores the originals when a group leaves the queue or the window closes.

## Smart trim and trimming precision

**Trim behaviour** is now one choice: **Smart · automatic**, **Manual
thresholds** (3.4.4's *Adaptive silence*) or **No trim**. Manual stays
selected, with your thresholds, until you choose Smart.

**Smart** learns start and end gates from each recording's own background and
level. It walks back through a soft attack, follows the decay, keeps one loud
click from raising the gate for a whole quiet asset, and keeps quiet audio when
it finds no steady background. It manages its own analysis passes. It is
deterministic signal analysis, not a trained model, and cannot tell unwanted
room tone from an intended ambience bed. Preview it, and use Manual where
material needs a specific threshold.

- **Per-item files are cut from the analysis render.** REAPER ignores the time
  selection when rendering selected items, so a correctly trimmed per-item file
  in 3.4.4 could render at full length and fail its length check. Each file is
  now a slice of a 32-bit float analysis render, and takes, stretch markers and
  automation are left alone.
- **A tail that outruns the scan stops the export.** With manual thresholds and
  2 passes, 3.4.4 cut such a tail in a combined render and added a note. The
  export now asks for 3 passes, which scan up to 30 seconds. Smart always has
  that budget.
- **Drift-free reads.** The detector steps on one integer sample clock instead
  of summing 10 ms steps, and non-finite samples are rejected, not read as
  silence.

## Delivery preview

**Preview delivery (dry-run, no render)** lists the files an export would
write, after UCS renaming, queue numbering and **New version** or **Replace**
against the files present now. It says what happens to each: new, versioned,
replaced, renamed to protect a project source, or skipped as silent. Nothing is
rendered or changed, and any edit to settings, queue, selection or project
discards the preview.

Each row is also a **delivery sheet**: detected audio, the delivered window and
its duration, under the batch's loudness target. Rows that could not be
measured say so. On per-item rows, **A/B** plays the original item range or the
predicted delivery window through the project mix, before normalization and
encoding.

The **boundary preview** gains a dB grid, a ruler, zoom to the delivery, a
legend and a line at the effective opening gate. It now says correctly that it
reads the take before take FX, so rendered bounds can differ.

## Delivery checks, reports and hand-off

- **Quiet is not silent.** 3.4.4 failed any delivery peaking below −60 dBFS as
  "effectively silent". Only an all-zero file fails now; a very quiet one gets
  a note to audition it. Final peak and RMS cover the whole file, independent
  of trim thresholds.
- **Fade checks look at the fade**: the endpoint and first and last 2 ms
  against the requested ramp, so a valid short fade no longer fails because of
  audio beside it.
- **Peak and True Peak targets are judged** against your tolerance, or ±0.5 dB,
  and non-finite readings count as unavailable instead of passing.
- **`_DeliveryManifest.json`** joins the CSV and HTML report: the same verdicts,
  machine-readable, with queue-numbered files grouped into asset families
  (`Bow_01`, `Bow_02` → `Bow`) for Wwise, FMOD or Unity hand-off.
- **Game SFX level review.** **Game SFX · keep level** replaces 3.4.4's
  *Mobile game · −16 LUFS* quick target and enables an optional review. It flags
  peaks below −36 dBFS or at −0.1 dBFS and above, true peaks over 0 dBTP, and
  MP3/OGG files with under 1 dB of headroom. These are hints only: no gain
  change, no extra render, no failed delivery. It is off by default.
- **Media Explorer.** **After export** offers **Stay here**, **Open system
  folder** (the default) or **Open Media Explorer**, which selects the file
  without playing it. Nothing opens unless the export fully succeeded.
  **Play in REAPER** and **Play** in History audition through the Media
  Explorer.
- **Workflow profiles** also remember trim mode, thresholds, timing and UCS
  identity. Built-in profiles and those saved by 3.4.4 leave what they never
  captured alone.

## Interface

- **Compact settings.** 38 choice buttons in 11 settings became dropdowns that
  show the current value. **Advanced delivery options** folds RF64 and report
  tolerance away but still summarizes them, and controls that do not apply hide
  without losing their values. Export stays in view while you scroll.
- **Segoe UI** on Windows, with Inter as fallback, clearer text and a graphite
  and teal palette.
- **Motion.** Render progress animates, pages fade in, and a confirmation names
  the delivered file. **Motion and transitions** in the F1 help turns the
  animation off.
- **Shortcuts survive a click.** In 3.4.4, clicking any control silenced `V`
  and the page keys. Now only a text field in use or an open popup holds them.
  F1 help lists them all, including `7` for Groups and `Q`.
- **Truthful labels.** "Use take name" is no longer clipped to "Use take nan",
  and the WAV large-file choices read **Project / Wave64** and **RF64 over
  4 GB**, which is what they always did. A Preflight scan that fails on opening
  reads "Not checked yet", not a pass.

## Fixed: what reached the delivery folder

**Combined render could deliver the next sound on the same track.** When
AutoTrim silences the rest of the timeline, it spares the tracks your selection
plays through. A neighbouring variation on those tracks, inside the tail scan,
stayed audible and was delivered: a sound, a silence, then a sound you never
selected. Spared items now stay audible only while they play across your
selection. Re-export any combined delivery that came out longer than your
selection, with extra hits after a gap.

**Forced WAV bit depths, every one.** REAPER stores the literal bit count, but
3.4.4 wrote an index (a 24-bit request sent `2`), so files did not ship at the
forced depth. The built-in Game / Wwise, Unreal Engine, EBU R128, ATSC A/85 and
Netflix profiles all force one. **Check your library** and re-export what does
not match. Auto-depth WAV was always correct.

**UCS names could shift fields.** CreatorID `Acme/Sound` became two fields, a
custom CatID's underscores became separators, and an empty CreatorID or SourceID
moved every later field. Forbidden characters inside a field, and underscores
in a custom CatID, now become `-`; empty required fields read `NONE`; and a
name over 180 characters shortens FXName instead of losing its last fields.

**Muted items no longer widen a selection.** **Select overlapping** collected
muted items, whose length pushed the tail scan into the next sound. They are now
skipped and counted; items you select by hand stay selected.

## Also fixed

- Muting some layers no longer blocks the export. It warns ("3 of 10 selected
  items will not reach the mix") and blocks only when nothing audible is left.
- A delivery named like `UI_Error.wav` no longer turns a success red. The
  outcome now comes from the engine, not from searching the status text.
- Replace mode keeps a verified render when a file appears at the target name
  at the last instant.
- A directory named like a delivery can no longer pass for a file on macOS or
  Linux, and Linux now really uses the no-clobber `ln -T`. A drive-root
  destination such as `C:\` no longer empties the loudness report.
- Saving a delivery profile no longer discards stored profiles it cannot read.
  History and the Undo journal merge with what another open AutoTrim window
  stored.
- Without SWS, a short file reads "LUFS-I unavailable" rather than "too short",
  and the report CSV now opens as UTF-8 in spreadsheets.
- The final review also fixed a retried cleanup that could misname the next
  queue group's file, a rolled-back replacement that blocked later Undo, and a
  file-name search that could hang REAPER on an unreachable volume.

## Requirements

- REAPER 7.37 or newer (64-bit) and ReaImGui 0.10.0.5 or newer in the 0.10
  series, unchanged from 3.4.4. SWS stays optional.
- **New on macOS and Linux:** the export folder's filesystem must support hard
  links, with `/bin/ln` available. Where the hard link fails, as on FAT/exFAT
  and some network mounts, AutoTrim stops. 3.4.4 fell back to a rename that
  could overwrite another program's file. Export to a supported folder and copy
  the files afterwards. Windows is unaffected.

## Verification

326 engine scenarios pass (171 in 3.4.4), as do 173 interface contract checks
(89 in 3.4.4). Those checks also run seven behavioural suites, from queue
workflow to compact settings and the waveform, with 140 more scenarios. Every
behaviour fix from the final review has a regression test that fails without
it.

CI passes on Windows, macOS and Linux. The Linux run also compiles every shipped
Lua file with native Lua 5.4, the version REAPER embeds, and runs both suites
on it. The Windows run builds the package under Windows PowerShell 5.1 and
PowerShell 7, verifies each build with the installer, and confirms both carry
an identical payload. Before publication the release was also exported by hand
in REAPER 7.61 on Windows: WAV, FLAC, OGG and MP3, combined and per-item,
new-version and replace, cancellation and display scaling.

## Upgrading

Close every AutoTrim window. Rename the old `AutoTrim Exporter` folder in
`Scripts` to a backup, copy in the complete new folder, and delete the backup
once the new version runs. On Windows, `Install-Windows.cmd` does this for you.
The launcher path is unchanged, so your action and toolbar buttons keep
working. See `INSTALL.md` in the package, including checksum verification.

Settings, delivery profiles, name lists, export history and the Undo journal
carry over. On the first run:

- Trimming stays on Manual thresholds until you choose Smart.
- **After export** starts on **Open system folder**.
- The window forgets its dock and position once, because 3.4.4 keyed them to a
  title that included the version. Its size carries over, and from now on dock
  and position survive updates.
- Name lists are capped at 5,000 names, 256 KiB and 4,096 bytes per row. A
  longer list saved by 3.4.4 is cut at the first entry past a limit.
- To add trim mode, timing and UCS identity to a 3.4.4 profile, apply it and
  save it again under the same name.
